C++20 · Web app · Technical analysis

MarketLens

A C++ server that loads daily stock prices from several countries and central-bank interest-rate decisions, computes technical-analysis indicators from them, and shows everything in a browser chart.

Short version Detailed version

In one paragraph

You pick a stock in the browser. The browser asks the MarketLens server for data. The server gets the price history (from saved files, or live from Alpha Vantage or Twelve Data), checks that every price is valid, and calculates moving averages, momentum, risk figures and support/resistance lines. It also checks how the stock moved the day after each interest-rate decision of its country's central bank. The answer goes back as JSON, and the page draws a chart from it. Many people can ask at once: a pool of threads handles requests in parallel, and results are cached so the same question is never computed twice.

What happens when you click “Anzeigen”

  1. The catalog says what exists.

    A JSON file (config/katalog.json) lists each security with symbol, name, country and currency, and each central bank with the countries it is responsible for. Adding a country means adding a line, not changing code.

  2. The server loads the prices.

    Offline it reads saved API answers from daten/. Live, it calls the provider over HTTPS and stores the answer on disk so the small free quota lasts. Every candle (open, high, low, close, volume) is checked for consistency.

  3. It calculates the analysis.

    SMA, EMA, MACD and RSI for trend and momentum; Bollinger bands, ATR, returns, volatility and maximum drawdown for risk; support/resistance levels and pivot points; and the event study for rate decisions.

  4. It answers many requests at once.

    A thread pool works on requests in parallel. A shared result cache remembers answers for 5 minutes, and if two people ask the same thing at the same moment, it is computed only once.

  5. The browser draws it.

    Plain HTML and JavaScript, served by the same server, draw the candle chart with indicators, level lines, rate-decision markers, RSI and MACD panels. You can draw your own trend lines, and every number has a “?” that explains it.

Why it is built this way

  • The network sits behind interfaces, so all tests run offline with recorded answers.
  • The analysis code doesn’t know about the server, so it can be tested on its own.
  • Free API quotas are small, so answers are cached on disk with an expiry time.
  • API keys come from environment variables and never enter the repository.

Providers

  • Alpha Vantage for all six securities (global symbols with exchange suffix like .DEX). Key: ALPHAVANTAGE_API_KEY. About 25 free calls a day.
  • Twelve Data for IBM and AAPL (F3). Key: TWELVEDATA_API_KEY. About 800 free calls a day.
  • Each provider has a parse function (JSON → Kursreihe) and a bewerte function that tells the cache whether an answer is good, an error, or a quota hit, since both providers sometimes send errors with status 200.

Interest rates from FRED

FRED has no list of “decisions”. It has the policy rate for every day (series DFEDTARU for the Fed, ECBDFR for the ECB). FredQuelle::leiteEntscheidungenAb creates one decision for every day the rate changes, one per country of the bank. Unchanged-rate meetings are invisible in this data, and the first day never counts.

E7

Disk cache for API answers

src/http/http_cache.cpp · src/basis/uhr.hpp

CachingHttpClient wraps another IHttpClient (decorator pattern). For each URL it keeps a file with the answer and the time it was fetched.

SituationWhat happens
Entry exists and is freshReturn it. No network call.
Entry missing or expiredFetch again; store only if the provider’s bewerte says the answer is good.
File corrupt or incompleteIgnore it and fetch again instead of crashing.
Network down or quota used upReturn the old entry, even if expired, marked veraltet: true with a hinweis text. The UI shows this as a yellow note.

Expiry: 12 h for Alpha Vantage (25 calls a day for 6 securities means at most 12 calls a day), 1 h for Twelve Data. --gueltigkeit overrides it (1–168 h). Time comes from an IUhr interface; tests use a FakeUhr to jump 13 hours forward without waiting.

E3

Trend and momentum indicators

src/analyse/trendindikatoren.cpp · class Trendindikatoren

Each indicator returns an Indikatorreihe = std::vector<std::optional<double>>, one value per candle. Values before the warm-up period ends are nullopt (“not available”), so the chart can leave them out instead of drawing fake numbers.

IndicatorDefaultWhat it does
SMA20Average close of the last n days.
EMA20Average that weights recent days more: α = 2 / (n + 1), started with the SMA.
MACD12,26,9Line = EMA(12) − EMA(26); signal = EMA(9) of the line; histogram = line − signal.
RSI14Wilder’s RSI: 100 − 100 / (1 + avg gain / avg loss), between 0 and 100.

Period ≤ 0, a series that is too short, or MACD with fast ≥ slow are rejected with an error. Tests compare against values calculated by hand; the calculation is written in the test comment.

E4

Volatility and risk

src/analyse/risikokennzahlen.cpp · class Risikokennzahlen
Bollinger middle = SMA(20), upper/lower = middle ± 2 · σ(20) ATR(14) Wilder average of true range = max(H−L, |H−C₋₁|, |L−C₋₁|) simple return rₜ = Cₜ / Cₜ₋₁ − 1 log return rₜ = ln(Cₜ / Cₜ₋₁) volatility stdev(log returns) · √252 (252 trading days a year) max drawdown largest fall from a running peak, e.g. 120 → 90 = −25 %

Special cases are defined: constant prices give volatility 0 and drawdown 0; a series with one candle has no returns and volatility is “not available” instead of an error.

E5

Support, resistance and pivot points

src/analyse/supportresistance.cpp · class SupportResistance
  1. Find local highs and lows.

    A day is a local high if its high is the largest within fenster days on each side (default 5). Edges without a full window are skipped; on a flat plateau only the first day counts.

  2. Group nearby prices.

    Prices within a relative tolerance (default 2 %) are merged into one level. The number of merged points is the level’s touch count: more touches means a stronger level.

  3. Classify and sort.

    Below the last close is support, above is resistance. The list is sorted ascending.

Classic pivot points from the last candle:

P = (H + L + C) / 3 R1 = 2P − L S1 = 2P − H R2 = P + (H − L) S2 = P − (H − L)
E6

Event study: price reaction to rate decisions

src/analyse/ereignisstudie.cpp · class Ereignisstudie

Question: how did this stock move on the trading day after its central bank changed rates?

  • Only decisions whose country equals the stock’s country count (MBG.DEX → ECB, IBM → Fed).
  • Reaction day = first trading day after the decision. A decision on a weekend or holiday maps to the next trading day.
  • Change = close on reaction day / close on the trading day before − 1.
  • Decisions outside the price history are skipped. A stock with no matching central bank (UK, Canada, India in the current catalog) gets an empty list, not an error.

Each result is an Ereignis: the decision, reaction day, price before, price after and the change.

E9

Concurrency: thread pool and shared cache

src/server/threadpool.cpp · src/server/ergebnis_cache.cpp · src/quellen/synchronisierte_quelle.hpp

ThreadPool

A fixed number of worker threads (default: number of CPU cores, --threads N to change) take jobs from a queue. beende() lets running jobs finish and joins every thread, so nothing hangs on shutdown.

ErgebnisCache

The cache key is path + sorted parameters. When a calculation starts, a std::shared_future is stored under the key. A second thread asking the same thing finds the future and waits for it instead of computing again. One std::mutex protects the map; the slow work runs outside the lock.

Result: answers are identical to a sequential run, whatever the number or order of requests, and identical requests are computed once. A stress test with a fixed random seed checks this within a time limit.

Clean shutdown. Before any thread starts, main blocks SIGINT and SIGTERM for all threads. A dedicated signal thread waits in sigwait(); on Ctrl+C it calls server.stoppe(). This runs as normal code, not inside a signal handler, where almost nothing is allowed.

Quality

Testing

tests/ · 224 GoogleTest cases
  • One test_*.cpp per module. All logic lives in the library projekt_lib, so tests run without main.
  • FakeHttpClient replays recorded real answers from tests/fixtures/ (Alpha Vantage, Twelve Data, FRED), plus small hand-written broken ones: invalid JSON, missing field, error 401/404/429, inconsistent candle, duplicate date.
  • FakeUhr makes cache expiry testable without waiting.
  • The default build has no network and needs no extra libraries. Live HTTPS is a CMake option, checked by a manual test protocol (docs/testprotokoll.md).
  • A pre-commit hook builds and runs all tests before every commit.
